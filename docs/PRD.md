# 产品需求 · v0.1

## 已确认的用户要求

- 分析并复刻 IntelliJ IDEA 的 Git 版本管理体验，使用 Open Design 探索设计。
- 产品是独立 Git 客户端，不是 IDE 插件。
- 能对接本地 Claude Code、Codex 等 Agent。
- 针对 AI 大批量修改，使 Review 和多轮复审更容易。
- 需要真实 Agent 辅助 Review，不能只有人工 Diff 或复制提示词。
- 已认可暗色紧凑原型方向；已用 fde-study 真实未提交修改试用。
- 目前仅准备项目与开发材料，后续 Claude Code 接手实现。

## 目标用户与主要流程

本地 Agent 用户选择仓库 → 查看本轮变更 → 理解变更组与 Diff → 启动单文件/整批 Agent 审查 → 点击意见查看实际位置与依据 → 人工决定采纳/忽略 → 保存反馈并交给 Agent 修复 → 刷新/监视产生新快照 → 只复审受影响内容 → 完成人工审查 → 后续 Git 写操作提交。

## 首个可用切片（BR-001 至 BR-005）

1. 真正桌面窗口，原生选择本地仓库；最近仓库列表、打开失败原因与空状态。
2. 工作区相对 HEAD 的真实变更，包含 untracked、staged、unstaged、删除；中文/空格文件名。
3. 文件树/列表、变更统计、对齐双栏 Diff、全文视图。新增文件默认单栏。长行可读且左右行保持对齐。
4. 持久化人工审查、问题、反馈草稿；标记绑定实际内容与基线，变化后重新判定。
5. 本地 Agent 能力检测、单文件/整批审查、进度、停止、失败重试、有效报告校验、历史 run。
6. 意见区分 issue / verify，给出实际文件行号、依据与建议；点击定位；采用为草稿；过期检测。
7. 支持外部 Agent 修复后的人工刷新；第一版先做显式刷新，文件监视必须具备去抖、内容核验后再开启。
8. 展示 Agent/来源/验证范围的真实状态，不伪造“测试通过”。

## 后续 Git 客户端范围（BR-006 起）

- 文件级暂存与取消暂存、提交预览与提交；明确展示 index/worktree 差异。再扩展 hunk 操作。
- 分支列表、搜索、新建、checkout、提交图与详情、筛选联动。
- Fetch / Pull / Push 状态及失败恢复；merge/rebase 中断状态；三方冲突解决。
- 按意图分组、拖动分组、组级审查进度；审查状态随后细化至 hunk。
- Agent 编码会话管理、worktree 任务隔离、从反馈启动修复与重新审查。

## 不在首版承诺

云端账号/团队协作、托管仓库平台、替代所有 IDE 功能、自动批准变更、无人确认的 reset/force push、把本地 CLI 等同于离线模型、承诺 Agent 能验证没有提供的课程原文。

## 体验验收

- 用户看到意见后能在一次点击内到达对应文件和行；路径/行号无效的输出不能显示为可信定位。
- 新的外部修改不会使未变化文件全部重新审查，也不会保留已变化文件的绿色通过状态。
- 重启应用后保留审查记录与报告；多个仓库/基线之间不会串记录。
- 可从 Agent 意见形成足够具体的修复反馈；复制/导出不会静默截断内容。
- 3 轮真实任务分别覆盖代码、中文文档和混合批量变更，再决定工作流是否足够好用。操作性测试见 ACCEPTANCE.md。
