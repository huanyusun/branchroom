# 真实试用与验证方案

## 当前证据与边界

原型测试 8 项通过；Codex 对 fde-study 的 4 个真实变更文件完成一次 Review，意见定位/反馈草稿/报告重启恢复验证过。Claude 真调用失败。以上是原型证据，不等同于正式应用的单元、集成、桌面或打包测试。

正式实现首先用临时 fixture，再经用户选择真实仓库。不得为演示修改 fde-study，不把真实笔记和真实审查输出拷进本项目测试集。

## 自动化验证矩阵

| 层 | 必测行为 |
| --- | --- |
| 仓库识别 | 非 Git、取消、普通仓库、linked worktree、detached HEAD、无首个提交、中文/空格路径 |
| Git 快照 | staged+unstaged、untracked、delete、rename、conflict、无末尾换行、二进制、symlink、资源限制、捕获期间变化 |
| 审查存储 | 重启恢复、repo/worktree 分隔、基线变化、stage 不改变内容身份、局部失效、旧内容保存被拒、超长草稿不丢 |
| Agent 报告 | 正常/零意见、coverage 缺失、路径越界、base/current 行号错误、半个 JSON、错误 priority、重复报告、过期 |
| CLI 生命周期 | 未安装、auth/model 失败、慢输出、输出过量、取消、超时、后代进程、旧任务不影响新任务、应用退出 |
| 桌面 | 原生选择目录、退出/重启恢复、窗口缩放、长中文、键盘导航、Diff 定位、高亮、侧栏收起、构建产物启动 |

## 三轮试用

### A · 中文文档

经用户选择 fde-study；对新增复盘和 W02 笔记完整走一次审查。检查：长行对齐、单栏/双栏切换、Agent 是否给具体依据而非泛化提醒、待核实与课程事实错误是否混淆。原型已有此场景经验，可作为回归比较。

### B · 代码修复

使用独立测试仓库，包含异步请求重试或状态清理的真实缺陷、相关调用方和测试。Agent 审查找出的行为问题需能回到文件行并由测试/复现证实。无需模型固定返回某段话，自动化结构校验使用假 CLI。

### C · 混合批量修改与二次修复

独立仓库准备至少 20 个混合文件，含无关格式变化、业务变化、文档、测试。人审查部分文件后，仅修改其中两个；刷新并复审。检查是否还要从头重读全部文件、哪些报告失效、未变化记录是否保留、是否误把格式变化当成逻辑错误。

## 每轮记录

记录仓库类型和变更规模（不复制私有内容）、完成流程是否闭环、卡住的具体步骤、重复阅读次数、文件/意见跳转次数、误报/可核实意见、耗时与用户主观负担。首轮建立基线，不预先虚构“节省 50% 时间”的指标。

完成条件：核心流程没有阻断；可清楚辨别已读/待复审/未覆盖；有足够证据评估改进点。正式测试命令及截图/报告在实现后随对应提交补齐。
